## The Hook

When researchers at Amazon Web Services tested GPT-4o on low-frequency APIs, it produced valid invocations only 38.58% of the time. Adding documentation improved it to 47.94%. The implication is clear: your documentation is the difference between an AI coding assistant giving correct answers or hallucinating — and most docs aren't structured for either.

Here's the uncomfortable truth: documentation was written for humans. AI agents read it differently. They chunk it, retrieve it, and reason over it through pipelines that break when docs are structured the way we've always written them.

We analyzed 10 peer-reviewed papers from AWS, HKUST, Cloudflare, and top AI research labs to understand exactly where and why documentation fails AI coding assistants. The findings are specific, measurable, and fixable.

---

## Two Pipelines, Two Failure Modes

Before diving into the findings, it helps to understand how AI actually consumes your documentation. There are two distinct pipelines — and each breaks in different ways.

| | AI Search Pipeline | AI Coding Agent Pipeline |
|---|---|---|
| **How it works** | User query → retrieval system finds relevant doc chunks → LLM synthesizes an answer | Agent receives a task → autonomously searches, reads, and reasons over docs → generates code |
| **What breaks** | Poor chunking, missing metadata, ambiguous headings → wrong chunks retrieved | Flat structure, verbose pages, missing examples → agent loops and hallucates |
| **Key research** | MDP (Model-Document Protocol) | DeepRead, ContextBench |
| **Failure cost** | Wrong answer served to user | Agent burns tokens looping through unhelpful pages |

Most documentation teams optimize for neither. The research shows this has measurable consequences.

## 5 Research-Backed Failure Patterns

### 1. Flat structure causes agent loops

**Source:** DeepRead — Document Structure-Aware Reasoning (arXiv, 2025)

When AI agents encounter documentation with flat or poorly nested heading structures, they struggle to navigate efficiently. The research found that agents make **10.4 tool calls on failed document reads vs. 7.7 on successful ones**. That 35% overhead isn't just wasted compute — it's the agent cycling through irrelevant sections because the document structure doesn't signal where to look.

**What this means for your docs:** Every H2 and H3 is a navigation signal for AI agents. Flat pages with a single heading level force agents to read linearly instead of jumping to the relevant section.

---

### 2. Missing code examples cause a 3–4x accuracy drop

**Source:** HKUST — When LLMs Meet API Documentation (arXiv, 2025)

Researchers systematically removed individual documentation elements to measure their impact on AI code generation accuracy. The result: **removing code examples caused the single largest accuracy drop** — more than removing parameter descriptions, return types, or any other element.

APIs with working code examples saw 3–4x higher pass rates than those with only textual descriptions. The LLM doesn't just read your example — it uses it as a structural template for generating correct invocations.

**What this means for your docs:** Every API endpoint, SDK method, and configuration option needs at least one working code example. Not a snippet — a complete, copy-pasteable example.

---

### 3. Bad retrieval is worse than no retrieval

**Source:** AWS — On Mitigating Code LLM Hallucinations with API Documentation (arXiv, 2024)

This finding is counterintuitive: providing the wrong documentation context to an LLM produces worse results than providing no documentation at all. Specifically, sub-optimal retrieval caused a **39-point absolute accuracy drop for high-frequency APIs** compared to oracle (perfect) retrieval.

The problem isn't that retrieval fails entirely — it's that it retrieves something plausible but wrong. The LLM then generates code that confidently uses the wrong API pattern.

**What this means for your docs:** How your documentation chunks during retrieval matters enormously. Long pages that blend multiple API concepts get retrieved as a block, contaminating the context with irrelevant information.

---

### 4. Without documentation, LLMs hallucinate 85% of private API calls

**Source:** Towards Mitigating API Hallucination in Code Generated by LLMs (arXiv, 2025)

For private or internal APIs — anything not in the LLM's training data — hallucination rates reach approximately **85%**. The model has no grounding, so it invents plausible-looking but entirely fictional method signatures, parameter names, and return types.

This isn't a model quality issue. It's a documentation availability issue. The moment you provide structured documentation, hallucination rates drop dramatically.

**What this means for your docs:** If you maintain internal APIs, SDKs, or proprietary tools, your documentation isn't optional — it's the only thing standing between your AI coding tools and complete fabrication.

---

### 5. Concise sections outperform verbose pages

**Source:** SWE-ContextBench — A Benchmark for Context Retrieval in Coding Agents (arXiv, 2025)

When researchers compared how much context AI agents actually need to solve coding tasks, they found that **204-word targeted summaries outperformed 24,765-word full repository traces**. More context didn't help — it hurt.

This directly contradicts the instinct to "document everything." AI agents perform better with dense, well-structured sections than with comprehensive but verbose pages.

**What this means for your docs:** Aim for sections under 500 words per heading. If a section runs longer, break it into sub-sections with descriptive headings. The AI agent can then retrieve just the relevant chunk instead of processing the entire page.

## 3 Things You Can Do Today

You don't need to rewrite your entire documentation. Start with the three changes the research shows have the highest impact:

### 1. Add at least one working code example per API endpoint
The HKUST research showed this is the single highest-leverage change you can make. Not a fragment — a complete, runnable example that an LLM can use as a template.

### 2. Break sections longer than 500 words
The DeepRead threshold is clear: agent navigation degrades above ~500 words per heading. Audit your H2 density and split long sections with descriptive sub-headings.

### 3. Serve Markdown or structured formats to AI consumers
If your docs are HTML-only, AI agents waste tokens parsing markup. Adding a Markdown-accessible version (or `llms.txt`) reduces token consumption by up to 80% and improves retrieval accuracy.
